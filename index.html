01 / RESEARCH LOOP

근거를 쌓는 순서

각 단계의 산출물을 연결하고 상태 전이를 검사합니다. 역사 재현만으로 현재 V8의 새 버그를 주장하지 않습니다.

01 — SOURCE

CVE와 패치

공개 공지, fix commit, 회귀 테스트의 출처와 해시를 고정합니다.

02 — REPLAY

역사적 차이

동일 조건의 취약 부모와 수정 빌드에서 동작 차이를 반복 확인합니다.

03 — MIGRATE

현재 경로

보존된 불변식과 변이 가능한 차원을 현재 V8의 FuzzIL generator로 옮깁니다.

04 — MEASURE

통제 실험

동일 예산의 비교군, 실행 로그, target hit, coverage, crash를 분리해 읽습니다.

02 / CURRENT EVIDENCE

현재까지 확인한 것

수치와 한계 자세히 보기 ↗
INTEGRATION

다섯 generator가 동작합니다.

Wasm GC 두 계열, TurboFan receiver-map, parser eval-scope, Maglev allocation-folding 전략을 현재 Fuzzilli 실행에 연결했습니다.

CONTROL PATH

Agent의 제안이 다음 window에 적용됩니다.

B2의 weight 제안·검증·적용 경로를 Codex·Claude CLI 두 provider로 확인했습니다. v3 통제 실험에서 발동 쌍에 1→100 action이 적용됐습니다.

LIMITATION

적응의 일반 우월성은 미입증입니다.

v7의 양의 신호가 미러(v8)에서 재현되지 않고 약한 음으로 뒤집혀, 방향 특정 artifact로 판단했습니다. 전체 coverage·corpus 우월성은 판정하지 않습니다.
