01 / PROJECT FOCUS

V8을 다시,
정밀하게 조준합니다.

LLMVF는 V8을 재학습하거나 임의로 수정하는 프로젝트가 아닙니다. 이미 알려진 취약점의 패치와 실행 근거를 읽고, 방대한 JavaScript 상태 공간에서 다음 탐색이 집중되어야 할 위치와 조건을 더 정밀하게 정의합니다.

01

근본 원인패치가 막은 메커니즘을 구조화합니다.

02

트리거 조건취약 동작에 필요한 상태 조합을 좁힙니다.

03

변종 경계패치 주변의 아직 검증되지 않은 가능성을 탐색합니다.

02 / 연구 방법

근거를 입력하고,
실험으로 답합니다.

모델이 추론한 내용과 퍼저가 실행한 작업, 그리고 실험으로 입증할 수 있는 결과를 하나의 추적 가능한 파이프라인으로 연결합니다.

01
⌁

취약점 근거 수집

보안 권고문, 패치 차이, PoC 메타데이터와 영향받는 리비전을 구조화합니다.

  • CVE 기록
  • 패치 문맥
  • 버전 경계
02
◇

취약점 구조화

근본 원인과 발생 조건을 추출하고, 인접 변종에 대한 검증 가능한 가설을 만듭니다.

  • 발생 조건 명세
  • 변종 가설
  • 표적 함수
03
↯

퍼저 유도

가설을 Fuzzilli가 사용할 수 있는 시드, 생성기, 가중치와 템플릿으로 변환합니다.

  • 검증된 지침
  • 대응 시드 계보
  • 동일한 자원 예산
04
∿

차이 측정

커버리지, 충돌, 재현 여부와 소요 시간을 기준으로 기본 실험과 유도 실험을 비교합니다.

  • 대응 표본 통계
  • 효과 크기
  • 검증 가능한 보고서

03 / ARCHITECTURE

하나의 추론을
다섯 겹의 검증으로.

각 계층의 입력과 출력이 분리되어 있어, 모델의 제안이 실제 실행과 측정 결과로 이어지는 전 과정을 추적할 수 있습니다.

TRACEABLE PIPELINE / BOTTOM → TOP
05

평가 및 보고

커버리지, 재현, 충돌과 통계 결과를 감사 가능한 형태로 출력합니다.

04

대응 실험

동일한 시간·연산·시드 조건에서 Baseline과 Guided 실험을 실행합니다.

03

지침 생성 및 검증

가설을 Fuzzilli 지침으로 변환하고 실제 표적에 도달하는지 먼저 검증합니다.

02

LLM 변종 분석

근본 원인, 트리거 명세와 인접 변종 가설을 단계적으로 생성합니다.

01

근거 및 실행 계층

CVE·패치·PoC 메타데이터와 V8·Fuzzilli 실행 환경을 연결합니다.

04 / 평가

지침은 가설이고,
근거가 결과입니다.

모든 유도 실험은 시간, 연산 자원, 메모리와 시드 예산이 동일한 기본 실험과 짝을 이룹니다. 비교가 불완전하다면 그 사실도 결과에 명확히 표시합니다.

TF

표적 함수 커버리지

취약점 분석이 지목한 코드까지 실제 실행이 도달했는지 확인합니다.

Δt

최초 신호 도달 시간

각 실험군이 관련 동작을 얼마나 빠르게 재현하거나 발견했는지 측정합니다.

UC

고유 충돌

중복을 제거한 뒤 유효한 sanitizer 시그니처가 얼마나 남았는지 셉니다.

A₁₂

효과 크기

관측된 차이가 단순한 숫자 증가를 넘어 실질적으로 의미 있는지 평가합니다.

05 / 연구 원칙

성급한 결론에
저항하도록 설계합니다.

01

시간적 분리

미래 지향 실험에서는 패치와 PoC를 모델에 제공하지 않아 정보 누출을 줄입니다.

02

공정한 비교

기본 실험과 유도 실험은 동일한 빌드, 예산, 자원과 시드 계보를 공유합니다.

03

실패가 보이는 보고

누락된 대응쌍, 잘못된 환경과 불완전한 근거를 보고서에 명시적으로 남깁니다.

04

오프라인 우선

고비용 도구를 연결하기 전에도 시뮬레이션 백엔드로 전체 흐름을 검증할 수 있습니다.
