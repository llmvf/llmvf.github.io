02 / SUPERVISOR PIPELINE

생성은 Agent가,
판정은 증거가.

LLM은 trigger와 seed를 제안하지만, 환경 무결성·실행 유효성·semantic finding과 통계 결론은 deterministic gate가 판정합니다.

⌁

  • Leakage Guard
  • Held-out Lock

◇

  • Agent Feedback

  • Agent Loop

03 / EVIDENCE LADDER

도달과 발견 사이를
숨기지 않습니다.

현재 대시보드는 단순 reproduced 표기 대신 finding이 어느 증거 단계에 있는지 표시합니다.

01Target Reached

취약 관련 코드에 도달했지만 finding은 아님

02Candidate

crash 또는 semantic signal이 queue에 등록됨

03Confirmed Known CVE

vulnerable에서 재현되고 fixed에서 사라짐

04Confirmed Variant

최소화·중복 제거·원인 분석까지 통과함

04 / RESEARCH INTEGRITY

좋은 결과만 남기지
않도록 설계합니다.

positive·neutral·negative 결과를 보존하고 기술적으로 invalid한 epoch만 격리해 checkpoint에서 복구합니다.

01

분리된 데이터셋

development, validation, held-out split을 성능 확인 전에 고정합니다.

02

공정한 네 arm

동일한 seed, 예산, CPU 조건에서 Stock부터 Agent까지 비교합니다.

03

실패 격리와 복구

startup self-test, CPU collision, 환경 오류는 invalid로 분리합니다.

04

과장 없는 판정

rare event 표본이 부족하면 성공 대신 underpowered로 표시합니다.
