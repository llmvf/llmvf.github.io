재현에서 발견까지,
연결된 증거로.

Experiment Manager가 상태·예산·corpus 승격을 통제하고, 에이전트의 제안은 스키마와 게이트를 통과한 후에만 다음 실행에 반영됩니다.

LINEAGE

검증 가능한 연구 계보

case → hypothesis → mapping → strategy → campaign → run → finding → report. 단계마다 입력, 출력, 출처와 실패 상태를 남깁니다.

01

Evidence

공식 출처와 commit을 연결해 CVE case를 만들고, 역사적 parent/fix를 반복 실행합니다.

02

Mechanism & Mapping

관찰된 실패 불변식을 가설로 분리하고 현재 V8 코드에 남은 경로를 찾습니다.

03

Strategy & Campaign

FuzzIL generator와 oracle을 제안하고 revision, corpus hash, seed, CPU, 예산을 동결합니다.

04

Run & Review

REPRL·coverage·입력 유효성 게이트를 통과한 run만 분석하고 후보는 독립 재현 후 검토합니다.

COMPARISON DESIGN

같은 현재 V8에서 비교

서로 다른 V8 버전의 raw coverage는 비교하지 않습니다. 비교군은 동일 초기 corpus, CPU, 시간과 실행 상한을 사용합니다.

B0 / BASELINE

Stock Fuzzilli

전용 CVE 전략을 넣지 않은 기준선.

B1 / FIXED

CVE 전략

역사 재현과 현재 매핑을 거친 generator를 고정 가중치로 추가.

B2 / ADAPTIVE

단일 Agent

검증된 이벤트에 따라 다음 window의 전략 가중치를 변경.

B3 / PLANNED

역할 분리 Agent

다중 에이전트 비교군. 현재 공개 결과에 완료 run으로 포함하지 않음.

GUARDRAILS

무엇을 확인해야 하는가

실행 가능성, 메커니즘 노출, 성능, 발견은 별개의 판정입니다.

01 / 환경

V8·Fuzzilli·toolchain revision, binary와 입력 SHA-256, REPRL/coverage 상태를 검증합니다.

02 / 공정성

arm별 corpus를 분리하고 같은 시작점과 예산을 적용합니다. 승인된 변경은 다음 window부터 반영합니다.

03 / 관찰

target 구조가 실제 corpus에 남았는지 확인하고 edge coverage, 유효 입력, timeout, crash를 별도 집계합니다.

04 / 발견

후보를 축소·중복 제거·독립 재현한 뒤 사람 검토를 거쳐 finding으로 승격합니다.
